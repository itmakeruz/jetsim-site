# JetSim: единый визуальный стиль

## Реализация

Главная сохраняет кинематографический фотографический hero и lime-акценты. Тарифы, корзина, оплата, авторизация и личный кабинет используют общую палитру midnight navy / тёплый белый / lime, локальный Manrope и согласованные кнопки, поля, панели и модальные окна.

На мобильных экранах — компактная шапка с точно центрированным логотипом, переключателем языка и корзиной; нижняя плавающая навигация с safe-area и активным состоянием по маршруту. Desktop использует верхнее меню. Поддержка размещена с учётом нижних элементов управления. Анимации учитывают reduced motion.

Язык RU/EN и фильтры тарифов используют общий PremiumSelect на Radix: клавиатурная навигация, typeahead, Escape, выбранное состояние, portal. Флаги — локальные SVG. Профиль и «Мои eSIM» используют общий контейнер с шапкой; карточки корзины уплотнены. Шаги оплаты — тонкие индикаторы с иконками вместо нумерованных кругов.

Фотографии и промпты описаны в [ASSETS.md](ASSETS.md). Цены и тарифы берутся из существующего API. Совместимость устройства не определяется по декоративной анимации: демонстрация явно предлагает проверить EID.

## Неоплаченные eSIM и оплата существующего заказа

Причина прежнего ложного «Выпуск eSIM…»: backend создаёт SIM со статусом CREATED уже при подготовке оплаты. Теперь API списка SIM дополнен payment_status канонической транзакции. CREATED без подтверждения оплаты отображается как «Ожидает оплаты» без polling выпуска. SUCCESS и WAITING_ORDER_CONFIRMATION трактуются как оплаченные состояния. Возврат, отмена и ошибка показываются отдельно.

Кнопка «Оплатить заказ» вызывает защищённый JWT маршрут:

`POST /payment/orders/:id/payment-link`

Он проверяет владельца, CREATED заказа, PENDING транзакции, сохранённую HTTPS-ссылку, статус платежа в банке (NEW / FORM_SHOWED), затем повторно проверяет PENDING после запроса банка. Возвращает ту же ссылку. Новая транзакция, заказ и новый Init не создаются. Ошибки банка возвращаются безопасно; чужой заказ — 404, неподходящий статус или отсутствующая старая ссылка — 409.

При начальном Init ссылка сохраняется в существующем Transaction.request как payment_url вместе с прежними данными запроса. Поля статуса и webhook response при этом не меняются. Миграция и новые переменные окружения не нужны. Старые ссылки, которые раньше не сохранялись, автоматически не восстанавливаются: интерфейс предлагает обратиться в поддержку с номером заказа.

Документация банка: [Init](https://developer.tbank.ru/eacq/api/init), [платёжная форма](https://developer.tbank.ru/eacq/scenarios/payments/nonPCI). Ссылка используется из ответа банка, а не конструируется из PaymentId.

## Проверка

- Frontend: сборка и тесты фильтрации/состояний выдачи. ESLint без ошибок, остаются три прежних предупреждения зависимостей useEffect в App.tsx.
- Backend: сборка, профильные тесты подготовки Mobiline, проверки платежей, прав доступа, повторного открытия ссылки, параллельного webhook и проекции статуса оплаты.
- Главная и оплата проверены на 320, 375, 390, 430, 768, 1024, 1440, 1920 px: [viewport-qa.json](viewport-qa.json).
- Профиль проверен отдельно на тех же ширинах с изолированными данными и отключённой сетью. Контент выровнен с контейнером навбара.
- Новые карточки оплаты проверены на тех же ширинах без горизонтального переполнения: [payment-status-viewport-qa.json](payment-status-viewport-qa.json). Кнопка присутствует только у ожидающего оплаты заказа. Проверено сообщение ошибки при отключённой сети.
- Проверены гостевая корзина и изменение количества, поля email/промокода без отправки OTP и проведения покупки, языковой dropdown на мобильном экране.

Скриншоты в screenshots/: изображения с суффиксом fixture показывают изолированные тестовые данные, не реальный аккаунт. Временная страница проверки удаляется после QA и не входит в production.

Реальная оплата и выпуск eSIM не запускались. Авторизованные сценарии с сохранением персональных данных не выполнялись. Для работы нового действия сначала развернуть backend, затем сайт; текущий production API не получает локальные изменения автоматически. Текущие изменения не опубликованы этим этапом.
