# Фото обложки и экран направлений

В dashboard открыть «Регионы» → «Регионы» (`/regions`) для стран или «Регион группы» (`/region-groups`) для групп. При создании/редактировании есть отдельное поле «Фото обложки» с превью, заменой и удалением. Флаг/иконка остаётся в прежнем поле. Рекомендация: 1600 × 1000 px, JPEG/PNG/WebP до 8 МБ, без надписей. Изменение сохраняется общей кнопкой формы.

Backend добавляет nullable `cover_image` к Region и RegionGroup. Существующие multipart create/update принимают поля `image` и `cover_image` отдельно. Для явного удаления используется `remove_cover=true`. Если обложка не передана, прежняя сохраняется. Файл хранится рядом с иконками соответствующей сущности; публичные/admin ответы возвращают путь в `cover_image`. Файлы обложек получают UUID и расширение по разрешённому типу. Обновление обложки не меняет флаг.

Сайт использует обложку на карточках главной, отдельного экрана `/countries` и заголовке тарифов конкретного направления. Если обложка не задана или не загружается, используется редакционное фото из проекта, для неизвестных направлений — нейтральная сцена аэропорта. Флаг не растягивается на фон.

В мобильной панели «Страны» открывает `/countries`: самостоятельный экран с поиском существующих направлений, категориями, пагинацией и переходом к рабочим тарифам. Категория хранится в URL `?type=...`; главный экран остаётся `/`.

Подтверждение совместимости eSIM сохраняется только после явного подтверждения в localStorage: `jetsim:esim-support-confirmed:v1=confirmed`. Следующие добавления не показывают модалку. Закрытие/отмена ничего не сохраняют. Первое подтверждение сохраняет прежнюю 10-секундную задержку. Это предпочтение данного браузера и origin, не автоматическая проверка устройства: при очистке данных, в другом браузере/режиме или на другом домене подтверждение потребуется снова. Для покупок на другое устройство совместимость проверяется отдельно.

Развёртывание: сначала применить миграцию `20261107050000_destination_covers` (`npx prisma migrate deploy`), затем `npx prisma generate`, сборка/restart backend, после этого обновить dashboard и сайт. Существующие записи получают NULL, данные и флаги сохраняются. Новых env-переменных нет. На production миграция в рамках этой задачи не применялась.

Проверка: тесты backend создания/замены/сохранения/удаления обложки и выдачи URL, frontend тесты localStorage (включая недоступное хранилище), сборки трёх проектов. В браузере отдельно проверены превью и удаление файла без отправки данных на сервер, первичная модалка, отмена и повторный показ, подтверждение и отсутствие модалки после перезагрузки на изолированном origin. Production-записи не редактировались. ESLint сайта: три прежних предупреждения App.tsx; конфигурация ESLint dashboard не разбирает TypeScript-аннотации, поэтому его проверка ограничена сборкой и UI.

В браузере проверен мобильный переход из нижней навигации на `/countries`, переключение категорий с обновлением URL и поиск «Япония» с переходом в `/tariffs/ids=19`. Экран визуально проверен при фактической ширине 390 px без горизонтального переполнения; запрошенные через инструмент другие размеры в этой сессии не применились и не засчитываются как проверенные.
